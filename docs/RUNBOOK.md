# Operational runbook (private beta)

- Startup: verify configuration, private data directory, stable master key, `/health`, authenticated `/capabilities`, offline smoke tests. Check mode reports `openrouter` or `deepseek` only when configured. The model adapter uses one request (max two attempts), 30-second per attempt timeout, 4 simultaneous model calls, 10 requests/min/account. Proxy should also rate-limit other endpoints. No claimed latency or throughput benchmark.
- Jobs: `AWAITING_APPROVAL` needs a human decision; five-minute expiry. `COMPLETED` means the operation ran; `crypto.verify` may return valid=false. `FAILED` has safe error code. `REJECTED` includes expired, user rejection, changed source/key/destination. Never replay an approval. On uncertain network result GET the existing job before creating another. Use stable idempotency key for retried direct `/jobs` requests. Expired pending jobs become REJECTED when approval is attempted; no background reaper. Multi-step requests are manually staged, not auto-executed.
- Wrong key/tampered token: no output published, originals preserved. Restore proper key or request a new exact proposal. Lost key: do not reset the master key for an existing database. Back up key material separately from state. Replacing/removing encryption keys can make old ciphertext unreadable; verify backups first.
- SQLite: one worker, BEGIN IMMEDIATE and savepoints for transactions. Database metadata and encrypted BLOBs stored together. Use SQLite's backup API or stop service before taking a consistent filesystem snapshot. Protect data directory, backup and master key. Test restoring to a separate private directory. No live file copy of a running database without a SQLite-consistent backup. Quotas intentionally bound stored objects and jobs; implement retention/cleanup before long-running public usage. Clearing activity does not erase job records or backups.
- Unexpected errors: stop and inspect job state; log only error class/safe request IDs. Do not enable verbose HTTP request logging. Model 401/429/503: check account access and limits, use offline smoke mode for deterministic tests; do not automatically execute a different operation. Rotate compromised API/access tokens. If suspected exposure, take beta offline and revoke keys/tokens. Use separate access tokens per tester and regenerate on revocation (restart to apply env changes).
- Rollback: tag known-good source after tests; preserve backup of state and master key; deploy prior code version only if DB schema compatible. Git rollback does not undo data changes. Restore data only with owner approval and confirmed scope. Do not force-push.
- Linux: lab resource metrics describe backend environment, not the user's PC; disabled by default. Enable only on a dedicated disposable VM or appropriately isolated lab. Never run public chatbot with unrestricted shell, root, Docker socket or host filesystem access. Script preview is fixed diagnostic example; execution uses fixed Python functions, not arbitrary generated scripts.
